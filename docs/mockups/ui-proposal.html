§01 — Workflow

How a run works

No SDK, no code changes. The run executes on your machine against your provider; the report is a local file.

  1. env var

    Provide a key

    Read on your machine, sent only to the provider you selected — never to ModelCheck, never as a command-line argument.

  2. pre-flight

    Configure

    Pin the exact model ID and suite version. Case counts, omissions and an estimated charge are printed before the first request is billed.

  3. local file

    Inspect

    Per-capability scores with n, sample outputs, latency, estimated charge, failures — every number linked back to its cases.

§05 — FAQ

Questions, answered exactly

Direct answers, no hedging.

All docs →
What does a run cost?ModelCheck charges nothing. Your provider bills you; a pre-flight estimate is shown before the run and --spend-limit refuses to start above your limit.
Who can see my key?Nobody but your provider. There is no ModelCheck server — reports are local files under RUNS_DIR.
Can I reproduce a result?Every report pins model ID, provider, parameters, suite version and timestamp, exportable with its methodology manifest.
